Getting started with ng-ql

An Eloquent-inspired HTTP request and query builder for Angular — built on HttpClient, Signals, and RxJS. It is not an ORM: no database, no models, no identity map. It builds, serializes, executes, caches, and types HTTP requests against your REST API.

1. Install

Only @angular/core, @angular/common, and rxjs are required — nothing else.

2. Register the provider

provideNgQl sets the base URL, default headers, and default cache behavior for every resource in your app.

3. Define a model and a resource

A model is a plain TypeScript interface — no base class, no decorators. A resource extends NgQlResource and points it at an endpoint.

4. Query it — Observable API

Every read returns an RxJS Observable, exactly like HttpClient itself.

5. Query it — Signal API

Every read also has a Signal-based twin exposing data, loading, error, and status — with built-in caching.

7. Object-form where, orWhere grouping, and the filter[...] envelope

where/orWhere accept an object of equality conditions instead of (field, value) — every entry is AND-ed together. Consecutive where() calls AND into the current group; orWhere() starts a new group OR-ed against everything before it. The default serializer's filter[...] wrapper is also optional — pass filterPrefix: null to DefaultNgQlQuerySerializer for backends that expect bare field names. Try the "Wrap filters in filter[...]" and "Generate as object-form" toggles in the Interactive console tab to see both live.

8. Create, update, patch, delete

Every mutation automatically invalidates the cache entries it affects.
